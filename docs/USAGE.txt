窗栏 WindowRail 1.0

一个纵向、透明、置顶的 Windows 文档窗口切换栏。

使用
1. 把整个文件夹解压到一个可写的位置，双击 WindowRail.exe。
2. 先打开 Word 文档或其他应用，再点底部 ＋，勾选希望添加的窗口。
3. 单击名称切换到对应窗口。最小化的窗口会恢复。同一 Word 中的不同文档分别显示。
4. 拖动顶部六个点移动整个窗栏；拖动条目改变顺序。
5. 右键条目可以设置显示别名、移动、移除或固定所属程序。
6. 顶部 ··· 菜单可调宽度、文字明暗、条目背景透明度、隐藏和退出。
7. 隐藏后，双击系统托盘中的窗栏图标重新显示。

外观
默认不显示条目底色，顶部拖动点、菜单和底部 ＋ 也没有可见底色。
按钮文字跟随条目文字颜色及阴影。当前窗口和鼠标悬停的条目有轻微高亮。
浅色桌面上可以开启“深色文字”；复杂背景可选择“轻透”或“清晰”。
图标外、条目与按钮以外的完全透明区域不接收点击。条目整行保留点击区域。

窗口与固定程序
窗口条目绑定某个具体窗口；关闭文档会移除该条目，不会关闭其他文件。
固定程序是单独的启动入口。程序正在运行时切回其最近使用的窗口，未运行时尝试启动。
一个程序可有多个文档条目，但只需一个固定程序入口。
程序只在托盘运行、没有可用窗口时，窗栏会提示手动唤起，避免重复启动。
无法识别 EXE 路径的窗口仍可切换，但不能创建可靠的固定启动入口。

配置与重启
配置自动保存在程序旁 data/settings.json，上一份有效配置保存在 settings.json.bak。
将整个 data 文件夹一并复制即可保留设置。
固定程序、排序、别名、颜色和位置会保留。
重开窗栏时，文档条目仅在程序路径和原窗口完整标题能唯一匹配时恢复。
若原窗口已经关闭，或存在多个完全同名的窗口，请通过 ＋ 重新添加。
这里没有将文档文件本身固定为启动快捷方式；关闭后重新打开特定文件需在 Word 中完成。
移动或升级程序前可先从 ··· 菜单退出。重复启动同一份窗栏只会显示已有实例。

适用范围
首版为 Windows x64 普通桌面应用，使用已公开的 Windows 窗口接口。
不同虚拟桌面的窗口不自动跨桌面切换；独占全屏、UAC 安全桌面不保证悬浮覆盖。
某些管理员权限程序、商店应用、宿主窗口和特殊启动器需要单独适配。
若 Windows 暂时拒绝前台激活，会显示提示并提醒目标窗口，可再次点击。
应用栏本身置顶；不会改变目标程序的持续置顶状态、大小和位置。
首版不包含开机启动或自动更新。

运行环境
已随包附带私有 .NET 10 运行环境，不需要另外安装，也不更改全局 .NET 设置。
请保留 runtime 文件夹及 WindowRail.dll 等配套文件，不要只复制 EXE。
运行环境和第三方许可位于 runtime/LICENSE.txt 与 runtime/ThirdPartyNotices.txt。

开发
源码使用 C# / WPF / Win32 API，无额外第三方 NuGet 依赖。
安装 Windows x64 的 .NET 10 SDK 后，在仓库根目录运行 scripts/build.ps1。
逻辑验证：运行 scripts/test.ps1。
生成便携 ZIP：运行 scripts/package.ps1。
完整技术路径和维护方法见仓库 README.md。
开发验证参数：--data-dir <独立配置目录> --test-ui。
正常使用无需命令行参数。--test-ui 仅使测试窗口可以被辅助工具定位。
